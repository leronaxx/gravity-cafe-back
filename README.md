# Gravity Café — сайт кафе с ИИ-ассистентом

Дипломный проект: веб-сайт кафе с меню, предзаказом, бронированием столиков
и **ИИ-ассистентом**, который помогает гостю выбрать блюда и напитки,
рассказывает о калорийности и составе, сообщает адрес, часы работы и историю
кафе.

## Состав проекта

| Часть | Технологии | Где лежит |
|---|---|---|
| Фронтенд | HTML, CSS, JavaScript, Vite | корень репозитория (`index.html`, `src/`) |
| Бэкенд | Node.js, Express | `server/` |
| База данных | PostgreSQL | `server/seed/schema.sql` |
| ИИ-ассистент | RAG + function calling, Ollama / OpenAI-совместимый API | `server/assistant/` |

## Быстрый старт

### 1. База данных

```bash
# Создать базу (если ещё нет)
createdb gravity_cafe

# Применить схему и заполнить данными
psql -d gravity_cafe -f server/seed/schema.sql
cd server && npm install && npm run seed
```

Если база уже была создана раньше, примените миграцию, которая добавляет
данные для ИИ-ассистента (калорийность, БЖУ, аллергены, таблицы логов):

```bash
psql -d gravity_cafe -f server/seed/migrations/001_assistant.sql
```

### 2. Настройки бэкенда

```bash
cp server/.env.example server/.env
# откройте server/.env и укажите доступ к PostgreSQL
```

### 3. Запуск

Нужны два процесса: бэкенд (API и ассистент) и фронтенд (Vite).

```bash
# Терминал 1 — бэкенд, порт 3000
cd server && npm start
```

```bash
# Терминал 2 — фронтенд, порт 5173 (Vite проксирует /api на :3000)
cd ..
npm install
npm run dev
```

Если открывать страницы без Vite (двойным кликом или через `npx http-server .`),
фронтенд обратится к API напрямую по адресу `http://localhost:3000/api` —
бэкенд всё равно должен быть запущен.

### 4. Языковая модель для ассистента

Ассистент работает с любым из вариантов:

* **локально (бесплатно, офлайн):** установить [Ollama](https://ollama.com),
  выполнить `ollama pull qwen2.5:7b-instruct` и указать в `.env`
  `ASSISTANT_PROVIDER=ollama`;
* **облако:** указать `ASSISTANT_PROVIDER=openai` и ключ `OPENAI_API_KEY`
  (подходит любой OpenAI-совместимый сервис: OpenAI, DeepSeek, OpenRouter);
* **без языковой модели:** `ASSISTANT_PROVIDER=mock` — ассистент отвечает
  детерминированным поиском по базе знаний. Такой режим включается
  автоматически, если модель недоступна, поэтому сайт не ломается.

## ИИ-ассистент

### Как он отвечает

1. Вопрос гостя поступает на `POST /api/assistant/chat/stream`.
2. **RAG:** ретривер ищет в базе знаний (37 фактов о кафе) самые близкие
   к вопросу факты по TF-IDF и косинусной близости.
3. Агент добавляет к промпту актуальное меню из PostgreSQL.
4. Языковая модель при необходимости **вызывает инструменты**
   (`search_menu`, `get_menu_item`, `get_cafe_info`,
   `search_cafe_knowledge`, `get_popular_items`), которые выполняют
   параметризованные SQL-запросы, — поэтому цены и калории всегда точные.
5. Ответ уходит гостю потоком (Server-Sent Events) и печатается постепенно.
6. Диалог записывается в `assistant_messages`; гость может оценить ответ 👍/👎.

### Эндпоинты

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/api/assistant/chat` | ответ одним JSON |
| POST | `/api/assistant/chat/stream` | ответ потоком (SSE) |
| POST | `/api/assistant/feedback` | оценка ответа |
| GET | `/api/assistant/health` | состояние ассистента и провайдера |
| GET | `/api/assistant/stats` | статистика диалогов |
| GET | `/api/assistant/suggestions` | подсказки для чата |
