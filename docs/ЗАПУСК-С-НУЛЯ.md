# Запуск проекта с нуля

Пошаговая инструкция: от чистого компьютера до работающего сайта с ИИ-ассистентом.
Все команды проверены — если выполнять их по порядку, всё заработает.

Инструкция рассчитана на macOS (проверялась на Apple M1). Для Windows и Linux
отличия указаны отдельно.

---

## Что понадобится

| Программа | Зачем | Версия |
|---|---|---|
| **Node.js** | на нём работает бэкенд и сборка сайта | 20 или новее |
| **PostgreSQL** | база данных: меню, заказы, брони, логи ассистента | 14 или новее |
| **Git** | скачать проект с GitHub | любая |
| **Ollama** (необязательно) | локальная языковая модель для ассистента | последняя |

Без Ollama сайт тоже работает: ассистент отвечает по базе знаний и данным из
PostgreSQL, просто менее «живым» текстом.

---

## Шаг 1. Установить программы

### macOS (через Homebrew)

Если Homebrew ещё не установлен — поставить его с [brew.sh](https://brew.sh),
затем:

```bash
brew install node postgresql@16 git ollama

# запустить базу данных и модель как службы (будут стартовать сами при входе)
brew services start postgresql@16
brew services start ollama
```

Проверить, что всё встало:

```bash
node --version        # v20.x или новее
psql --version        # psql (PostgreSQL) 16.x
git --version
ollama --version
```

### Windows

1. **Node.js** — установщик с [nodejs.org](https://nodejs.org) (кнопка LTS).
2. **PostgreSQL** — установщик с [postgresql.org](https://www.postgresql.org/download/windows/).
   При установке запомните пароль пользователя `postgres`.
3. **Git** — с [git-scm.com](https://git-scm.com/download/win).
4. **Ollama** — с [ollama.com](https://ollama.com/download).

Дальше команды выполняются в **PowerShell**. База данных уже запускается
автоматически как служба Windows.

### Linux (Ubuntu/Debian)

```bash
sudo apt update
sudo apt install -y nodejs npm postgresql git
sudo systemctl start postgresql
# Ollama:
curl -fsSL https://ollama.com/install.sh | sh
```

## Шаг 2. Скачать проект с GitHub

Проект состоит из **двух репозиториев**. Удобнее положить их рядом, в одну папку:

```bash
mkdir -p ~/Projects && cd ~/Projects

git clone https://github.com/leronaxx/gravity-cafe-back.git
git clone https://github.com/leronaxx/gravity-cafe-front.git

cd gravity-cafe-back
```

Что где лежит:

| Репозиторий | Что внутри |
|---|---|
| `gravity-cafe-back` | бэкенд на Node.js + Express, база данных, ИИ-ассистент, документация, а также второй вариант фронтенда на Vite |
| `gravity-cafe-front` | статичный сайт кафе: HTML, CSS, JavaScript |

> Если при клонировании Git спросит логин и пароль — нужен **личный токен доступа**
> GitHub (Settings → Developer settings → Personal access tokens), обычный пароль
> не подойдёт. Либо настройте SSH-ключ.

## Шаг 3. Создать базу данных

```bash
createdb gravity_cafe
```

Если команда `createdb` не найдена, укажите полный путь или добавьте PostgreSQL
в `PATH` (на macOS: `export PATH="/opt/homebrew/opt/postgresql@16/bin:$PATH"`).

Проверить, что база появилась:

```bash
psql -l
```

**Таблицы создавать вручную не нужно** — их создаст следующий шаг.

---

## Шаг 4. Настроить бэкенд

```bash
cd ~/Projects/gravity-cafe-back/server
cp .env.example .env
```

Откройте `.env` в любом текстовом редакторе и заполните доступ к базе:

```ini
PG_HOST=localhost
PG_PORT=5432
PG_DATABASE=gravity_cafe
PG_USER=denis            # ← ваш логин в системе (macOS/Linux) или postgres (Windows)
PG_PASSWORD=             # ← на macOS/Linux обычно пусто; на Windows пароль из установки
PORT=3000
```

Остальные строки (`ASSISTANT_*`) можно пока не трогать — там уже разумные
значения по умолчанию.

**Как узнать свой логин:** выполните `whoami`. На macOS и Linux у PostgreSQL
из Homebrew/репозитория нет пароля у пользователя-владельца системы, поэтому
`PG_USER` — это ваш логин, а `PG_PASSWORD` пустой.

## Шаг 5. Установить зависимости и заполнить базу

```bash
# всё ещё в папке server
npm install
npm run seed
```

`npm run seed` создаёт все таблицы и наполняет их: 24 картинки, 3 категории,
3 зоны, 20 столиков, 15 временных слотов, 18 блюд с калориями и БЖУ,
7 настроек кафе и таблицы для логов ассистента.

Ожидаемый результат в конце:

```
=== Seed complete ===
```

> ⚠️ **Важно.** Команда `npm run seed` **полностью очищает базу** и создаёт
> таблицы заново. Все заказы и бронирования будут удалены. Не запускайте её на
> рабочей базе с реальными данными — только при первой установке.

Перейти в корень проекта (для фронтенда на Vite) и поставить его зависимости:

```bash
cd ..
npm install
```

## Шаг 6. Запустить бэкенд

```bash
cd ~/Projects/gravity-cafe-back/server
npm start
```

В консоли появится:

```
Server running on http://localhost:3000
AI assistant: POST http://localhost:3000/api/assistant/chat
```

**Это окно не закрывайте** — сервер должен работать, пока вы пользуетесь сайтом.
Проверить, что всё живо, можно в браузере:
[http://localhost:3000/api/assistant/health](http://localhost:3000/api/assistant/health)

---

## Шаг 7. Открыть сайт

Есть два варианта.

### Вариант А — статичный сайт (проще)

Откройте файл `~/Projects/gravity-cafe-front/index.html` двойным щелчком.
Виджет сам найдёт бэкенд на порту 3000.

Если браузер ограничивает работу со страницей, открытой с диска, поднимите
локальный веб-сервер в папке фронтенда:

```bash
cd ~/Projects/gravity-cafe-front
npx http-server . -p 8080
# затем откройте http://localhost:8080
```

### Вариант Б — сайт со сборкой Vite (в репозитории бэкенда)

```bash
cd ~/Projects/gravity-cafe-back
npm run dev
```

Vite поднимет сайт на `http://localhost:5173` и сам перенаправит запросы
`/api` на бэкенд.

В правом нижнем углу страницы появится кнопка **«Спросить ИИ»**.

## Шаг 8. Подключить языковую модель (Ollama)

Без этого шага ассистент работает в режиме поиска по базе знаний — отвечает
верно, но шаблонным текстом. С моделью он начнёт отвечать живым языком.

```bash
# 1. Скачать модель (≈1,9 ГБ; хватит для 8 ГБ оперативной памяти)
ollama pull qwen2.5:3b-instruct

# 2. Проверить, что Ollama отвечает
ollama list
```

Затем в файле `server/.env` укажите:

```ini
ASSISTANT_PROVIDER=ollama
OLLAMA_MODEL=qwen2.5:3b-instruct
OLLAMA_TIMEOUT_MS=180000
```

и **перезапустите бэкенд** (`Ctrl+C` в его окне, затем снова `npm start`).

> Если у вас 16 ГБ памяти и больше, вместо 3b можно взять `qwen2.5:7b-instruct` —
> ответы будут качественнее, но медленнее и займут ≈4,4 ГБ на диске.

Проверить, что модель подключилась:

```bash
curl http://localhost:3000/api/assistant/health
```

В ответе должно быть `"provider": "ollama"` и `"degraded": false`.
Если `"provider": "mock"` — модель не подхватилась, смотрите поле `reason`.

## Шаг 9. Проверить, что всё работает

**Через браузер:** откройте сайт и задайте ассистенту вопросы:

* «Сколько калорий в тирамису?» → 420 ккал
* «Какие блюда до 300 ккал?» → список от эспрессо (5 ккал) до макаронс (240 ккал)
* «По какому адресу вы находитесь?» → Ростов-на-Дону, ул. Пушкинская, 151
* «Что посоветуете к кофе?» → рекомендация от языковой модели

**Через терминал:**

```bash
# состояние ассистента
curl http://localhost:3000/api/assistant/health

# обычный вопрос
curl -X POST http://localhost:3000/api/assistant/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"Сколько калорий в тирамису?"}'

# статистика диалогов
curl "http://localhost:3000/api/assistant/stats?days=1"
```

**Автоматические тесты** (из папки `server`):

```bash
npm test              # 43 юнит-теста — быстро, без базы и без модели
npm run test:db       # 34 проверки на живой базе PostgreSQL
npm run test:widget   # 59 проверок виджета (нужен запущенный сервер)
```

Третья команда ищет файлы сайта в соседней папке `gravity-cafe-front`.
Если папка называется иначе, укажите путь:

```bash
GRAVITY_FRONT_DIR=~/Projects/gravity-cafe-front npm run test:widget
```

Ожидаемый результат: `Все проверки виджета пройдены.`

## Шаг 10. Как обновлять проект

Когда в репозиториях появляются новые версии:

```bash
cd ~/Projects/gravity-cafe-back
git pull

cd ~/Projects/gravity-cafe-front
git pull
```

После обновления бэкенда:

```bash
cd ~/Projects/gravity-cafe-back/server
npm install     # если менялся package.json
npm start
```

Если в обновлении была новая миграция базы (файл в `server/seed/migrations/`),
её нужно применить — иначе ассистенту не хватит данных:

```bash
psql -d gravity_cafe -f ~/Projects/gravity-cafe-back/server/seed/migrations/001_assistant.sql
```

Повторять `npm run seed` при обновлении **не нужно** — он стирает данные.

## Если что-то пошло не так

| Сообщение | Причина | Что делать |
|---|---|---|
| `database "gravity_cafe" does not exist` | база не создана | выполнить `createdb gravity_cafe` |
| `password authentication failed for user "postgres"` | неверный пользователь или пароль в `.env` | проверить `PG_USER` (`whoami`) и `PG_PASSWORD` |
| `relation "menu_items" does not exist` | не выполнен `npm run seed` | выполнить `npm run seed` в папке `server` |
| `EADDRINUSE: address already in use :3000` | порт занят другим процессом | `lsof -ti:3000 \| xargs kill` (macOS/Linux) и запустить снова |
| В чате «Не удалось получить ответ» | бэкенд не запущен | запустить `npm start` в папке `server` |
| В шапке чата «Режим базы знаний (без языковой модели)» | Ollama не запущена или модель не скачана | `brew services start ollama`, затем `ollama pull qwen2.5:3b-instruct` |
| `npm error code EPERM` при установке | испорчен кэш npm | `sudo chown -R $(whoami) ~/.npm`, затем повторить `npm install` |
| `Unsupported engine` / странные ошибки Node | старая версия Node.js | обновить Node до 20+ |
| Модель отвечает дольше 30 секунд | мало оперативной памяти | это нормально для 8 ГБ; можно уменьшить модель (`qwen2.5:1.5b-instruct`) или переключиться на `ASSISTANT_PROVIDER=mock` |
| `createdb: command not found` | PostgreSQL не в `PATH` | `export PATH="/opt/homebrew/opt/postgresql@16/bin:$PATH"` |

## Шпаргалка: все команды подряд

Для macOS, если ничего ещё не установлено:

```bash
# 1. Программы
brew install node postgresql@16 git ollama
brew services start postgresql@16
brew services start ollama

# 2. Проект
mkdir -p ~/Projects && cd ~/Projects
git clone https://github.com/leronaxx/gravity-cafe-back.git
git clone https://github.com/leronaxx/gravity-cafe-front.git

# 3. База
createdb gravity_cafe

# 4. Настройки
cd gravity-cafe-back/server
cp .env.example .env
#    → открыть .env и указать PG_USER (ваш логин из `whoami`)

# 5. Зависимости и данные
npm install
npm run seed

# 6. Модель
ollama pull qwen2.5:3b-instruct

# 7. Запуск бэкенда (окно не закрывать)
npm start

# 8. Сайт: открыть файл ~/Projects/gravity-cafe-front/index.html
```

## Полезно знать

**Где что лежит в бэкенде**

```
server/assistant/     ИИ-ассистент: поиск по базе знаний, инструменты, провайдеры моделей
server/assistant/knowledge-base.json   37 фактов о кафе — можно править без перезапуска кода
server/routes/        HTTP-адреса API (меню, заказы, брони, ассистент)
server/seed/          схема базы, миграции и данные
server/tests/         автотесты
docs/                 документация, включая шпаргалку для защиты диплома
```

**Где документация**

* [ИИ-АССИСТЕНТ.md](ИИ-АССИСТЕНТ.md) — как устроен ассистент, все эндпоинты, тесты
* [ЗАЩИТА-ИИ-АССИСТЕНТ.md](ЗАЩИТА-ИИ-АССИСТЕНТ.md) — шпаргалка, вопросы комиссии, сценарий демонстрации
* [ГЛАВА-ДИПЛОМА-ИИ-АССИСТЕНТ.md](ГЛАВА-ДИПЛОМА-ИИ-АССИСТЕНТ.md) — черновик главы диплома

**Как поменять данные кафе** (адрес, телефон, часы работы) — это строки в
таблице `cafe_settings`:

```bash
psql -d gravity_cafe -c "UPDATE cafe_settings SET value='ваш адрес' WHERE key='address';"
```

После этого ассистент сразу отвечает новыми данными (кэш меню — 30 секунд,
настройки читаются при каждом запросе).
